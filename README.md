# Nextcloud OAuth2 для Jellyfin

**Русский** | [English](README.en.md)

SSO-плагин для **Jellyfin 12.1+**: пользователи входят в Jellyfin своей учётной записью
Nextcloud по протоколу OAuth 2.0 (auth code flow + OIDC discovery), без отдельного пароля.

| | |
|---|---|
| Имя пакета | `Nextcloud OAuth2` |
| GUID | `5c4de6ba-220f-4ace-9dce-72ba60c66861` |
| Категория | `Authentication` |
| Целевая ABI | Jellyfin `12.1.0.0` |

## Как это работает

1. Пользователь открывает ссылку входа `https://<jellyfin>/sso/OID/start/nextcloud`.
2. Плагин перенаправляет его на `/apps/oauth2/authorize` в Nextcloud.
3. Nextcloud возвращает пользователя на `https://<jellyfin>/sso/OID/redirect/nextcloud` с кодом.
4. Код обменивается на токен, данные пользователя читаются через OCS API
   (`/ocs/v2.php/cloud/user`), после чего выдаётся обычная сессия Jellyfin.

Сопоставление выполняется по **стабильному UID** Nextcloud → пользователю Jellyfin
(таблица привязок `UserLinks`); имя используется только как fallback.

## Установка

### Способ 1 — через репозиторий каталога (рекомендуется)

1. **Панель управления → Плагины → Репозитории → «+»**:
   - Название: `Nextcloud OAuth2`
   - URL: `https://raw.githubusercontent.com/exdeon/Jellyfin-Nextcloud-SSO/main/manifest.json`
2. **Панель управления → Плагины → Каталог** → *Nextcloud OAuth2* → **Установить**.
3. Перезапустите Jellyfin.

После этого обновления подтягиваются автоматически (встроенный таск *Plugin Updates*
запускается при старте сервера и раз в 24 часа).

### Способ 2 — вручную (sideload)

 1. Скачайте `Nextcloud-OAuth2-<версия>.zip` из [релизов](https://github.com/exdeon/Jellyfin-Nextcloud-SSO/releases).
2. Распакуйте в папку `Plugins/Nextcloud OAuth2_<версия>/` в каталоге конфигурации Jellyfin
   (в ней должны лежать `Jellyfin.Plugin.NextcloudOAuth2.dll` и `meta.json`).
3. Перезапустите Jellyfin.

> Плагин, поставленный только вручную, отсутствует в каталоге: страница плагина будет
> показывать «Произошла ошибка при получении сведений о плагине из репозитория».
> Чтобы этого не было (и работали обновления), подключите репозиторий из способа 1 —
> достаточно URL, папку на сервере трогать не нужно.

## Настройка

### 1. Nextcloud — зарегистрировать OAuth2-клиента

Откройте настройки безопасности администратора Nextcloud
(**Настройки → Администрирование → Безопасность**, прямой адрес `/settings/admin/security`)
и добавьте новый клиент:

| Поле | Значение |
|---|---|
| Название | `Jellyfin` |
| Redirect URI | `https://<jellyfin>/sso/OID/redirect/nextcloud` |

Nextcloud выдаст **Client Identifier** и **Client Secret** — сохраните их.

Примечания:

- Nextcloud поддерживает только confidential clients, Secret обязателен.
- Authorization endpoint: `https://<nextcloud>/apps/oauth2/authorize`
- Token endpoint: `https://<nextcloud>/apps/oauth2/api/v1/token`
  (если отключены pretty URLs — добавьте `/index.php`).
- Плагин передаёт `scope=openid profile email`; в текущих версиях Nextcloud скоупы
  фактически не применяются и токен даёт полный доступ к аккаунту пользователя.
- Чтобы убрать экран подтверждения при входе для доверенного приложения:
  `occ config:app:set oauth2 skipAuthPickerApplications --type array --value '["Jellyfin"]'`

### 2. Jellyfin — настроить плагин

**Панель управления → Плагины → *Nextcloud OAuth2* → настройки**:

| Поле в UI | Назначение | По умолчанию |
|---|---|---|
| URL сервера Nextcloud | Базовый адрес без слеша на конце | — |
| Client ID | Client Identifier из Nextcloud | — |
| Client Secret | Секрет из Nextcloud; пусто = оставить прежний | — |
| Публичный базовый URL | Внешний адрес Jellyfin, используется в redirect URI. Нужен за reverse-proxy без настроенных forwarded headers | пусто |
| Автоматически создавать пользователей | Создавать пользователя Jellyfin при первом входе | вкл. |
| Привязывать существующих пользователей по имени | Миграционная опция для старых версий плагина | вкл. |
| Использовать PKCE (S256) | Только если клиент Nextcloud зарегистрирован с поддержкой PKCE | выкл. |

Сохраните настройки и нажмите **«Проверить подключение»**. Ниже на той же странице
есть поле со ссылкой входа и кнопка «Копировать ссылку».

### 3. Войти

```
https://<jellyfin>/sso/OID/start/nextcloud
```

Параметр `?returnUrl=/` задаёт страницу, на которую вернуться после входа
(по умолчанию `#!/home`). Ссылку можно сделать страницей по умолчанию или добавить
в закладки пользователям.

### 4. Кнопка на экране входа (опционально)

Jellyfin показывает на странице логина произвольный HTML/Markdown — этим удобно
воспользоваться, чтобы поставить кнопку SSO рядом с обычной формой входа.

**Панель управления → Оформление → «Предупреждение при входе»**
(прямой адрес `/dashboard/branding`). Вставьте:

```html

<div style="text-align: center; width: 100%;">
    <div style="margin-bottom: 0.5em; opacity: 0.7; font-size: 0.9em;">или</div>
    <a href="/sso/OID/start/nextcloud"><span>🔐 Войти через Nextcloud</span></a>
</div>
```

Сохраните — блок выводится в нижней части страницы входа.

Что учитывать:

- Поле рендерится как Markdown с разрешённым HTML и проходит очистку DOMPurify.
  Оборачивайте разметку пустой строкой сверху и снизу, иначе markdown-it
  может не распознать её как HTML-блок.
- Не используйте на кнопке готовые классы Jellyfin (`raised button-submit`)
  и `is="emby-button"`: DOMPurify вырезает атрибут `is`, а скрипт страницы входа
  дополнительно вешает на каждую ссылку класс `button-link`
  (`_theme.scss` задаёт ему `color: primary`, `emby-button.scss` —
  `background: transparent`), из-за чего фон и текст схлопываются в один цвет.
  Своё правило `.nc-sso-btn` безопасно: `<style>` попадает в документ позже
  `<link>` в `<head>` и при равной специфичности побеждает.
- Jellyfin сам добавляет **каждой** ссылке в этом поле `target="_blank"` и
  `rel="noopener noreferrer"`, поэтому вход откроется в новой вкладке —
  после успешной авторизации закрывайте вкладку со старой формой.
- `href` указан относительным путём: кнопка работает и за reverse-proxy,
  и с заполненным «Публичным базовым URL».
- Сначала сохраните настройки плагина: иначе `/sso/OID/start/nextcloud` вернёт
  `400 Nextcloud OAuth2 не настроен`.

## Безопасность

- `ClientSecret` и привязки хранятся в `configuration.xml` **открытым текстом** —
  ограничьте доступ к файлу или контейнеру.
- После миграции всех пользователей отключите «Привязывать существующих пользователей
  по имени»: пока опция включена, входящий с неизвестным UID пользователь может занять
  существующий аккаунт Jellyfin с совпадающим именем.
- Токен Nextcloud даёт полный доступ к аккаунту — храните его только на сервере Jellyfin.
